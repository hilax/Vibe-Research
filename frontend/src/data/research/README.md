# 统一研究数据底座

本目录为 `AI算力 / HBM / 光互联 / 商业航天` 及八个扩展一级板块提供共用、可增量维护的数据底座。

- `types.ts`：来源、证据链、资产/项目卡、上市公司映射、催化剂、失败复盘、估值反证和跨板块关联 Schema。
- `sources.ts`：统一参考资料索引。每条来源记录发布日期、事件日期、数据期间、访问/最后核验日期、证据等级和交叉验证状态。
- `catalog.ts`：结构化产品/项目卡、公司映射、催化剂、失败复盘和关联边。
- `extendedSources.ts`：半导体国产替代、固态电池、低空经济、智能驾驶、创新药、电网与特高压、军工、可控核聚变的主来源。
- `specialCards.ts`：八类专属卡的完整字段和不可跨越阶段边界。
- `extendedCatalog.ts`：八板块的估值反证框架与跨板块主关联。
- `certainty.ts`：五维 0—5 分机械分档及运行时校验。
- 各板块的长文放在同级独立目录；八个扩展板块由 `../expandedSectors/` 的配置生成，页面组件不硬编码研究正文。

维护约束：

1. `null` 或空字段表示没有可靠公开数据，不用估算值补空。
2. 计划、样品、送样、验证、定点、核准、中标、小批、批量、交付、运营和收入按适用板块分别记录。
3. 统一五维为 `demand / technology / validation / delivery / financial`；旧记录的 `customer / capacity` 继续兼容。
4. 任何致命短板强制红档，不能被平均分掩盖；D/E级来源不得成为绿档结论的唯一依据。
5. 公司“涉及相关业务”不等于进入核心供应链、获得订单、形成收入或成为核心受益公司。
6. 创新药不复制药物事实，继续以 `../biopharma/` 的资产、临床数据、催化剂、失败案例和来源为主数据。
7. 军工无法公开核实的型号、客户、订单、性能、数量和交付字段必须写“公开信息不足”，不得用传闻或同类项目补全。
